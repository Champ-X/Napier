# Artifact consumer version binding

Artifact previews, diffs, downloads and inspector receipts now bind to the selected manifest snapshot. The shared receipt validator checks plan/artifact identity, plan revision, path digest, status, available thread/kind identity and declared content digest/size. Content reads require a valid digest and size even when the response omits them or mislabels its kind. Expected-content verification requires its expected digest; diff and uploaded-profile verification use their explicit identity mode. Every controller read validates its receipt. Existing lifecycle mutations retain their previous semantics.

The inline preview invalidates requests on a complete selection change, including a digest-only change, so an older response cannot appear under a newer selection. Downloads check returned identity metadata and actual byte size. Conversation cards and Changes distinguish historical integrity records from request-time matching, missing or drifted observations. Missing/drifted outputs and stale manifests do not reopen through the legacy output-path fallback. Changes derives deliverables from the plans rather than a partial conversation-event window.

Runtime, Web and native narrative projections share exact event/history/revision binding. An older event cannot acquire a newer manifest's contents. Native history binds its recording run and time; current/previous attempt labels are recomputed from primary-run and recovery intent context. A truncated event window that lacks relevant start events may omit an unbound card while the manifest-based deliverable remains available. The narrative cache version changes with these semantics.
