# 可合并的 coder 隔离工作区

G05-A 的候选现在保留创建时的工作区基线，在交付时保存私有候选，在应用时按读取依赖和写入目标检查当前工作区。两个不相交的改动不再因为整树摘要变化而互相作废。源目录中的未提交修改和未跟踪文件进入基线；不会 checkout、stash 或修改用户的 Git index。

## 选择与适用条件

| 方案 | 脏工作树 | Git 依赖与隔离 | 当前选择 |
| --- | --- | --- | --- |
| 普通 `git worktree add HEAD` | 不包含工作目录中的修改、删除和未跟踪文件 | 需要 Git，并共享仓库管理数据 | 不符合当前基线要求 |
| Git worktree + 当前内容覆盖 | 可以保留，但仍需捕获当前内容、确认删除、冻结基线并检查漂移 | 需要 Git，另有 index / refs / worktree 管理与清理成本 | 实测比较项，未进入执行默认路径 |
| 按文件的 COW 快照，失败时复制 | 直接捕获当前字节，包括未提交内容 | 创建隔离目录不依赖 Git，也不暴露共享 `.git` | 当前实现 |

这里的“快照”是逐文件的乐观捕获：检查 descriptor / path / inode / size / mtime / ctime，复制后核对内容，再扫描源树确认摘要。它不是文件系统原子快照；检测到捕获期间变化会拒绝交付不一致基线。文件系统不支持 `COPYFILE_FICLONE_FORCE` 时，按源／目标设备组合记住失败，避免为每个文件重复探测。复制从刚读取的有界 Buffer 写出，不使用硬链接。保留原文件权限和空目录。

本机 Node 接口返回 `ENOSYS`，所有规模样本实际采用普通复制。没有声称 APFS 本身不支持克隆，也没有以普通复制数据代替原生 COW 的磁盘节省证据。

## 基线、读取依赖和合并

- 私有 owner 目录保留独立的基线文件。只为声明的可写文件保留文本，其他源文件只保留路径、摘要、大小、mode；不把整树字节同时留在内存里。基线内容与 session 中的摘要绑定，候选无法通过修改隔离目录来改变原基线。
- 最终候选始终与该原基线比较，不再重新读取主工作区来充当基线。越过 writePaths 的文件修改、symlink 和特殊文件仍被拒绝。已有文件的 mode 修改明确拒绝，不静默漏掉；新增和移动文件保留相应 mode。
- 每个暴露给 coder 的工具均经过读取记录。单文件读取、数据／语法检查和 AST 工具按路径记录；search / symbols 按给定目录记录；list_files 记录名称集合；失败的不存在文件读取也保留依赖。命令、语义 LSP、调试器以及未知工具按整个可见源树保守记录，不能把直接 read_file 参数冒充完整 read-set。
- 合并只观察读取范围和改动目标。与这些范围无关的内容变动不会使结果失效。粗粒度工具读取过的全树内容发生变化时仍会阻断，需要重新验证；目前没有任意子进程的系统调用级精确读取跟踪。
- 三方合并使用保留的 baseline / 当前源文件 / candidate。未改动的源文件直接提交；同文件不重叠的文本改动通过 `git merge-file` 合并。冲突、新增目标已经存在、删除目标漂移和 mode 漂移明确停止，保留候选。非 Git 项目同样可以提交；只有同文件重叠需要 Git 的独立 `merge-file` 命令，缺失时停止并说明原因。
- 第一次 preflight 固定实际合并文本，原有诊断和关联测试据此捕获 before；第二次只检查依赖与目标，没有在诊断后再次自动改写合并内容。提交继续走原有多文件事务、路径锁、内容／inode 前置条件、回滚和后置条件检查，提交后进行原有诊断和关联测试。

检查是乐观并发控制，不能冻结不遵守 Napier 锁的外部编辑器或文件系统。三方文本合并也不证明语义正确；候选验证结果只描述原候选，合并后的诊断与相关测试另行给出，不构成整个用户目标的验收。

## 候选生命周期

交付先把候选保存到 `dataRoot/subagent-candidates`，成功后才清理 owner 目录中的隔离树和基线。该存储独立于旧的进程 owner 回收逻辑，目录为 0700、文件为 0600；候选 ID 绑定内容摘要、真实 workspaceRoot 和 dataRoot。LSP 完整编辑在读取时派生，持久对象不重复保存一份相同文本。

候选默认 7 天内可申请合并，保留 30 天供检查；容量为 128 个、1 GiB，总量或单对象 80 MiB 超限会明确失败，不静默淘汰结果。`inspectPreview` 可读取保留的 diff / 依赖／状态；`prunePreviews` 只清理超过保留期的明确候选。待对账或不确定提交不自动清理。当前未增加 Web 候选管理页。

同一候选应用有跨进程锁，路径别名规范化到相同身份。发生读取／文本冲突时不消费候选，解决主工作区冲突后仍可用原 ID 重试。提交前先持久保存 applying 标记；若进程随后被终止，重启保留候选并要求对账，不盲目执行。已持久结算的重试返回原收据且不写文件，并明确提示这是历史收据，没有重新核查当前文件。已验证且 durable 的完整回滚允许重新检查后重试；不确定结果不重放。

这是交付结果的持久化，不是完整 coder 执行中断恢复。自动对账 applying 状态、子代理上下文续跑、候选管理 UI、缺失父目录的事务创建，以及更精确的任意命令读取跟踪仍需后续工作。

## 有界资源策略

| 范围 | 上限与原因 |
| --- | --- |
| 可见源文件 | 50,000；源文件描述符逐个关闭，避免 descriptor 放大 |
| 可见目录／深度 | 50,000／64；限制遍历规模和递归深度 |
| 源字节／单文件 | 512 MiB／16 MiB；限制扫描、复制与单次缓冲区资源 |
| 可写文件／单个文本 | 32／1 MiB；与现有 32 文件事务上限对应；诊断选择上限同步为 32 |
| 基线 JSON | 64 MiB；最多保留 32 个可写文本及其余文件元数据 |
| 持久候选 | 80 MiB 单对象、128 个、1 GiB 总量；显式容量拒绝和保留期清理 |

对 generated / protected 目录继续采用原排除规则。没有将旧的 2k／32 MiB 限制直接改成无限制；replay 校验和委派 schema 同步采用新的 writePaths 上限。相关测试选择自身的有界／truncated 语义保持有效。

## 本地验证与测量

累计 13 个测试文件、64 个不同用例通过；最终交付／mutation 29 例覆盖最后的锁身份与事务排序修正。执行顺序与源码摘要见 `docs/artifacts/subagent-workspace-delivery-2026-10-29.json`，该收据明确保留累计验证的边界。

真实文件系统测试覆盖：脏 Git index 不变、未跟踪内容保留、两个独立候选交付、同文件三方合并、冲突后重启重试、正／负读取依赖、目录发现、未知工具保守读取、符号链接拒绝、诊断后漂移、基线／候选篡改、跨工作区绑定、存储过期和回收、路径别名竞争。独立进程在 commit 前后实际 SIGKILL，保留 applying 状态；独立进程竞争只有一次提交，丢失响应后的重试不改变目标 inode / mtime。

真实 Napier 仓库 smoke 使用两个同时创建的隔离候选，执行真实 TypeScript LSP、语义 rename、Node 调试器、命令和选中的 Vitest，再交付第二个候选并保留后来发生的无关修改。该 smoke 使用直接子进程 adapter，验证真实工具链和集成，没有重新证明 OS Sandbox 强制边界；本次没有修改生产 Sandbox 策略，没有模型请求。

规模收据：`docs/artifacts/subagent-workspace-scale-2026-10-29.json`。每个规模／方案使用三个独立进程，4 KiB 合成文件、脏工作区与未跟踪文件、交替执行顺序。下表时间为三次中位数，RSS 为三次观测峰值最大值，磁盘为 candidate + baseline 的 `stat.blocks` 统计（不含目录块；共享 extent 不能由此推断独占物理空间）。

| 文件数 | 自动 COW／回退 | 强制复制 | Git worktree + 脏内容覆盖 | 自动路径 RSS | 自动路径磁盘 |
| --- | --- | --- | --- | --- | --- |
| 5,000 | 2.444 s | 2.399 s | 2.346 s | 94.8 MiB | 20.60 MiB |
| 20,000 | 9.127 s | 9.817 s | 8.887 s | 178.9 MiB | 82.36 MiB |

本机自动路径全部回退普通复制，每个规模仅探测一次。小样本、温缓存及共享主机负载不足以证明方案速度优劣。旧 `3ba5bda7` fork 函数在两个规模均因 2,000 文件上限拒绝；它与当前部分未改 helper 配合运行，不是完整历史版本对比。旧样本 RSS 包括 TypeScript 转译器，不能与成功的新实现作内存比较。第一轮逐文件重复探测的原始数据保留在 ignored 的 `benchmark-results/subagent-workspace/scale-first.json`。

复现：

```sh
npm run build:compile -w @napier/runtime
node scripts/benchmark-subagent-workspace.mjs /tmp/new-workspace-scale.json 3
npm exec -w @napier/runtime -- vitest run test/subagent-worktree-delivery.test.ts test/subagent-worktree-mutation.test.ts --maxWorkers=2 --testTimeout=30000
NAPIER_LIVE_CODER_SUBAGENT_SMOKE=1 npm exec -w @napier/runtime -- vitest run test/live-coder-subagent-smoke.test.ts --maxWorkers=1 --testTimeout=180000
```

规模脚本独占创建输出，并对实际使用的源码和编译模块在测量前后核对摘要。运行真实仓库 smoke 时避免同时编辑仓库文件，因为语义 LSP／命令会保守记录整个可见源树为读取依赖。
