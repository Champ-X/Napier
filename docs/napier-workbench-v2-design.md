# Napier Workbench V2 设计规范

- 状态：实施基线
- 适用范围：Napier Web 桌面工作台
- 验证尺寸：1280×900、1440×900、1920×1080

## 1. 为什么需要 V2

上一阶段解决了间距、可访问性、滚动和组件一致性问题，但没有改变产品的视觉身份。顶部标题、页签、状态条、内容卡片与输入框仍然彼此割裂；会话、任务和轨迹虽然数据不同，视觉上却像同一个通用后台模板。用户首先看到的是容器，而不是正在执行的工作。

V2 的目标不是增加装饰，而是建立一眼可辨认的 Napier 工作模型：

1. 深墨导航负责“我在哪个项目、哪段会话”。
2. 编辑型画布负责“我正在和系统一起完成什么”。
3. 蓝色执行脊柱负责“系统如何从输入走到结果”。
4. 证据层负责“为什么可以相信这个结果”。

## 2. 视觉主张

Napier 是一个安静、精确、有工程判断力的 AI 工作台。它不像聊天软件，也不像指标看板；它更接近带执行能力的编辑器。

- 深墨侧栏形成稳定的项目边界，品牌蓝只承担活动状态、关键动作和执行脊柱。
- 主画布使用低饱和冷灰底与白色内容纸张，留白表达层级，不用大面积描边制造卡片。
- 标题使用紧凑字距和清晰重量；路径、哈希、时间、序号和 Token 才使用等宽字体。
- 绿色只表示已验证成功，琥珀只表示运行、等待或需要注意，红色只表示失败或破坏性动作。
- 禁止紫色渐变、玻璃拟态、发光阴影、满屏胶囊和卡片套卡片。

## 3. 工作台空间模型

```text
┌──────────────┬─────────────────────────────────────────────────────┐
│ 深墨项目导航 │ Command Bar：会话身份 / 视图 / 执行状态 / 模型 / 设置 │
│ 272 / 68 px  ├─────────────────────────────────────────────────────┤
│              │                                                     │
│ 最近项目     │  编辑型工作画布       蓝色执行脊柱       [证据层]   │
│ 当前项目     │  阅读轴 760-880 px                       320 px      │
│  └ 会话      │                                                     │
│              ├─────────────────────────────────────────────────────┤
│ 项目操作     │ 紧凑 Composer；聚焦后展开                            │
└──────────────┴─────────────────────────────────────────────────────┘
```

### 3.1 项目导航

- 展开宽度 272px，折叠宽度 68px，不新增中间态。
- 顶部只保留品牌、工作区身份和折叠动作；最近项目与当前项目会话树是主体。
- 当前项目以墨色选中面和 2px 品牌蓝指示表达，不使用浅蓝大色块。
- 当前会话是项目树的下一层，不合并不同项目的 `.napier` 历史。
- 底部放低频工作区操作；路径以等宽字体显示并允许截断。

### 3.2 Command Bar

- 高度 58px，替代“顶部标题行 + 第二条全宽状态条”的双层结构。
- 左区：会话标题和必要的路径上下文。中区：会话 / 任务 / 轨迹视图切换。右区：运行状态、模型和设置。
- 运行详情通过状态控件展开，不在普通状态下长期占用第二行。
- 活动视图用底部 2px 指示线和高对比文字表达，不使用独立圆角卡片。

### 3.3 编辑型工作画布

- 内容阅读轴目标 800px，允许 760-880px。普通会话在视觉中心稳定，不随证据层开关横跳超过 2px。
- 画布背景与内容纸张有轻微明度差；一级内容主要靠留白、排版与细分隔线分层。
- 阴影只用于浮层、Composer 和需要明确悬浮关系的面板。
- 证据层按需出现，固定 320px；承载产物详情、引用、校验和运行证据。

### 3.4 Composer

- 默认整体高度约 72px，输入区最小 44px；聚焦或输入多行时向上展开，最大 240px。
- 第一视觉层只包含输入、附件/上下文入口和运行按钮。工作区、模型准备度、运行选项放入次级控制区。
- readiness 默认表现为弱提示或状态点；仅在阻断运行时升级为高显著错误。
- 运行与停止按钮保持稳定位置，键盘行为和 steering/follow-up 能力不变。

## 4. 页面结构

### 4.1 会话

会话不是气泡列表，而是一条可追溯的执行叙事。

- 用户输入是脊柱上的输入节点，视觉更紧凑、带轻微蓝灰底。
- 助手回复以编辑正文呈现，不包裹厚重卡片。
- 工具、审批、计划、引用、产物和恢复记录作为脊柱事件；默认显示结论，详情渐进展开。
- 蓝色纵线贯穿同一轮执行，节点形状区分输入、推理/执行和完成。
- 空状态提供一句定位、一组可执行起点和当前工作区上下文，不展示营销式大标题。

### 4.2 任务

任务页从“卡片集合”改成三段式任务简报：

1. 顶部摘要：目标、状态、进度和当前步骤。
2. 中部执行：步骤序列沿执行脊柱展开，进行中步骤具有唯一的活动强调。
3. 底部证据：变更、环境和验证以结构化分区呈现；成功结果用短摘要，不铺满绿色。

概览 / 变更 / 环境 / 验证仍保留键盘可访问的视图切换，但外观与 Command Bar 的线性页签一致。

### 4.3 轨迹

轨迹是 Napier 最具辨识度的页面，应展示执行的时间和因果关系，而非另一组统计卡片。

- 顶部 masthead 只保留运行身份、覆盖率、耗时和导出动作。
- 筛选器是紧凑工具条。
- 事件列表使用连续纵向执行脊柱；时间、lane 和事件类型形成固定列。
- input、model、tool 保留各自允许的语义色，但脊柱活动态统一使用品牌蓝。
- advisor、loop guard、delegation 等高级面板遵循“摘要先行、证据展开”的规则。

### 4.4 设置

- 设置是居中的工作区级表单，不仿照系统偏好设置堆叠大量小卡片。
- 左侧分区导航固定，右侧表单宽度上限 800px。
- 每个分区只有一个标题和一段说明；字段使用稳定的 label / control / help / error 节奏。
- 保存结果在字段邻近区域反馈，不用全局彩色横幅。

## 5. 组件语言

| 组件     | 默认表现                 | 活动 / 选中           | 禁止做法                 |
| -------- | ------------------------ | --------------------- | ------------------------ |
| 主按钮   | 品牌蓝实心、40px 高      | 颜色加深，位置不抖动  | 渐变、发光、超大圆角     |
| 次按钮   | 透明或浅表面、32–36px 高 | 墨色文字 + 清晰边界   | 所有动作都做成蓝按钮     |
| 页签     | 线性文字导航             | 2px 蓝色底线          | 独立悬浮胶囊             |
| 内容分区 | 留白 + 细分隔线          | 标题或节点强调        | 每层都包卡片             |
| 状态     | 点 + 短标签              | 语义色仅用于状态      | 用整块彩色背景占据主视野 |
| 事件节点 | 蓝色脊柱 + 节点          | 当前节点有外环        | 每个事件随机一种品牌色   |
| 证据     | 摘要行，可展开           | 320px rail 或内联详情 | 默认展开全部原始数据     |

所有交互控件必须实现 hover、active、focus-visible、disabled；控件最小目标 32px，主操作最小 40px。只允许 opacity 和 transform 动效，使用 120 / 160 / 220ms，并支持 reduced motion 与 forced colors。

## 6. 三档桌面适配

### 1280×900

- 默认使用 68px 紧凑导航；用户展开后为 272px。
- Command Bar 可隐藏非关键辅助文字，但不得隐藏视图导航、运行状态和设置入口。
- 证据层以覆盖式 rail 出现，主阅读轴保持不位移。

### 1440×900

- 默认展开 272px 导航。
- 阅读轴保持 800px；证据层打开时从右侧覆盖或使用预留区，主轴位移不超过 2px。

### 1920×1080

- 导航保持 272px，不随宽度膨胀。
- 额外空间用于画布留白和证据层，不把阅读轴拉成宽屏正文。

## 7. 迁移顺序

1. 扩展 `DESIGN.md` 的导航、画布、脊柱、Command Bar 与 Composer 合同并重新生成 token。
2. 重构应用主壳、导航和 Command Bar，移除独立全宽状态层的视觉占位。
3. 重构会话节点和 Composer，使执行脊柱成为主叙事。
4. 将任务页改为摘要 / 执行 / 证据层级。
5. 将轨迹页统一到执行脊柱和固定信息列。
6. 收敛设置与高级面板，删除重复容器和无意义阴影。
7. 清理 `workbench-polish.css` 中已迁移的规则，避免长期依赖末端覆盖。

## 8. 验收标准

### 视觉

- 任意工作台截图都能明确识别深墨导航、浅色画布和蓝色执行脊柱。
- 会话、任务、轨迹三页具有共同语言，但无需读标题即可通过信息结构区分。
- 1280、1440、1920 三档下无横向溢出、遮挡、非预期滚动和焦点裁切。
- 证据层开关不使主阅读轴移动超过 2px。

### 交互与可访问性

- 导航树、顶层页签、任务页签、Composer、设置均可完整键盘操作。
- `focus-visible`、reduced motion、forced colors 和高对比模式合同继续成立。
- 原有运行、停止、steering、follow-up、模型、工作区切换、审批和产物导航行为不丢失。

### 工程

- `DESIGN.md` 是新增视觉语义的唯一来源，生成 token 无漂移。
- 关键结构写入组件和所属分层样式，不继续把 `workbench-polish.css` 扩成第二套设计系统。
- 类型检查、组件测试、设计预算、构建和三档浏览器 E2E 全部通过。
- 最终逐页检查会话、任务、轨迹、设置，以及运行中、完成、失败和空状态。
